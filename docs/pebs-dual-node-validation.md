# 阶段 2：PEBS 双 NUMA 节点热度验证

## 目的

验证真实 PEBS 数据能否按采样 CPU 所属 NUMA 节点聚合，并恢复已知的逐页访问偏好。
`shared_heat_bench` 创建一个 8 MiB、2048 页的共享匿名工作集：CPU 0（Node 0）
以 80:20 偏好前半页面，CPU 16（Node 1）以 80:20 偏好后半页面。

运行：

```bash
MIB=8 DURATION=5 SAMPLE_PERIOD=1000 THRESHOLD=2 \
  ./scripts/record_shared_heat_pebs.sh /tmp/hotpage-perf-check/shared-heat-pilot2
```

## Pilot 结果

- 原始 PEBS 样本 9721，工作集范围内有效样本 9581；
- 观测 1988/2048 页，页面覆盖率 97.07%；
- Node 0 样本 4567，Node 1 样本 5014；
- 前半工作集 Node 0:Node 1 = 3512:1158，即 3.03:1；
- 后半工作集 Node 1:Node 0 = 3856:1055，即 3.65:1；
- 前半 731 页、后半 744 页被正确判为偏好节点；两半各有 196、192 页方向错误，
  另有 65、60 页计数相同。

该结果证明当前 `perf record -> parse_perf_mem.py -> summarize_page_heat.py` 链路能够
同时获取 Node 0/1 的真实逐页访问样本，并恢复预设访问方向。方向错误主要来自每页样本数
仍较少的统计噪声，正式窗口需要用重复实验确定采样周期、持续时间与准确率的关系。

## 实现修正

线程栈可能与工作集形成较大的相邻匿名 mmap。基准现在直接报告工作集起止虚拟地址，
采集脚本通过解析器的 `--range START END` 显式过滤，避免“最大匿名映射”启发式扩大范围。
该地址只写入 `/tmp` 下的本次运行产物，不提交原始地址或 perf.data。

## 采样周期扫描

在 4 MiB、3 秒、阈值 2 的受控负载上扫描 `perf record -c`：

| 采样周期 | 有效样本 | 页面覆盖率 | 已判定页面准确率 | 全工作集正确覆盖率 |
|---:|---:|---:|---:|---:|
| 2000 | 3982 | 91.11% | 75.23% | 63.18% |
| 1000 | 7431 | 96.78% | 73.74% | 68.55% |
| 500 | 15617 | 99.41% | 73.46% | 72.17% |

周期 1000 的三次重复结果为：页面覆盖率 `95.70% +/- 0.43%`，已判定页面准确率
`72.93% +/- 0.13%`，全工作集正确覆盖率 `67.35% +/- 0.59%`（均值和样本标准差）。
因此当前 pilot 将 `SAMPLE_PERIOD=1000` 作为默认值：它在采样开销和覆盖率之间较平衡；
周期 500 只提高覆盖率，没有改善方向准确率。PEBS 数据适合作为热度排序信号，不能把
单页方向判断当作无噪声标签。
